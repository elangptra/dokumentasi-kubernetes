# Proses Install QEMU, KVM, dan Cockpit di Debian

## Nice To Have Concepts

### Penjelasan Sederhana

Anda ingin menjalankan **beberapa server sekaligus** di satu mesin fisik — misalnya server web, server database, dan server development — tanpa harus beli hardware baru.

Masalah tanpa virtualisasi:
- Satu mesin hanya bisa jalan 1 OS
- Kalau mau beda OS, harus beli server baru (mahal!)
- Resource server sering mubazir (CPU nganggur 80%, RAM tidak terpakai)

**Solusinya butuh 3 komponen:**

#### 1. **KVM (Kernel-based Virtual Machine)**

**Analogi Sederhana:**
- Tanpa KVM: Satu gedung hanya bisa ditempati 1 perusahaan
- Dengan KVM: Satu gedung dibagi jadi banyak ruangan, masing-masing punya kunci sendiri, AC sendiri, dan tidak ganggu satu sama lain

KVM adalah **hypervisor tipe-1** yang langsung terintegrasi ke kernel Linux. Artinya VM yang dijalankan performanya mendekati native — tidak ada lapisan OS tambahan yang memperlambat.

#### 2. **QEMU**

**Analogi Sederhana:**
- KVM adalah "ruangan"-nya, QEMU adalah "furnitur dan peralatan"-nya
- QEMU bertugas menyediakan emulasi perangkat keras (CPU virtual, disk virtual, network virtual) untuk setiap VM

QEMU bekerja bersama KVM: KVM menangani akselerasi hardware, QEMU menyediakan perangkat virtualnya.

#### 3. **Cockpit**

**Analogi Sederhana:**
- Tanpa Cockpit: Mengelola VM harus hafal puluhan perintah `virsh` di terminal
- Dengan Cockpit: Semua bisa dilakukan lewat **dashboard web yang visual** — buat VM, start/stop, monitor resource, cukup klik-klik di browser

**Singkatnya:**
- **KVM** → Engine virtualisasi yang nempel di kernel Linux
- **QEMU** → Penyedia perangkat keras virtual untuk setiap VM
- **Cockpit** → Dashboard web untuk kelola semua VM dengan mudah

## Persiapan: Cek Dukungan Virtualisasi CPU

**SANGAT PENTING!** Sebelum install KVM, pastikan CPU Anda mendukung virtualisasi hardware. Kalau tidak, KVM tidak bisa jalan.

### Cara Cek

Dari terminal, jalankan:

```bash
egrep -c '(vmx|svm)' /proc/cpuinfo
```

**Interpretasi hasil:**

| Hasil | Keterangan |
|---|---|
| `0` | CPU **tidak mendukung** KVM — aktifkan virtualisasi di BIOS/UEFI dulu |
| `≥ 1` | CPU **mendukung** KVM — instalasi bisa dilanjutkan ✅ |

> **Catatan:**
> - `vmx` = Intel Virtualization Technology (Intel VT-x)
> - `svm` = AMD Secure Virtual Machine (AMD-V)
>
> Jika hasilnya `0`, masuk ke BIOS/UEFI dan aktifkan opsi **Intel VT-x** atau **AMD-V** sebelum melanjutkan.

📝 **Angkanya lebih dari 0? Lanjut ke instalasi!**

## Langkah-Langkah Instalasi

### LANGKAH 1: Masuk ke Server

1. Buka **Terminal**
2. Jika server remote, login via SSH:

```bash
ssh username@192.168.x.x
```

✅ **Sudah masuk? Lanjut!**

---

### LANGKAH 2: Update Sistem

Pastikan semua paket sistem dalam kondisi terbaru sebelum instalasi dimulai.

```bash
sudo apt update && sudo apt upgrade -y
```

**Tunggu sampai selesai.** Proses ini bisa memakan waktu beberapa menit tergantung koneksi internet dan kondisi sistem.

✅ **Update selesai? Lanjut!**

---

### LANGKAH 3: Install QEMU, KVM, dan libvirt

Install semua paket inti yang dibutuhkan untuk menjalankan virtualisasi.

```bash
sudo apt install -y qemu-kvm libvirt-daemon-system libvirt-clients bridge-utils virtinst
```

**Penjelasan paket:**

| Paket | Fungsi |
|---|---|
| `qemu-kvm` | Emulator perangkat keras + akselerasi KVM |
| `libvirt-daemon-system` | Daemon `libvirtd` sebagai layer manajemen VM |
| `libvirt-clients` | Tools CLI seperti `virsh` untuk kelola VM dari terminal |
| `bridge-utils` | Utilitas konfigurasi network bridge untuk VM |
| `virtinst` | Tool `virt-install` untuk membuat VM dari command line |

**Output:** Akan muncul banyak baris proses download dan instalasi. Tunggu sampai kembali ke prompt terminal.

#### Verifikasi: Cek Status libvirt

Pastikan service libvirt sudah berjalan:

```bash
sudo systemctl status libvirtd
```

**Output yang diharapkan:**
```
● libvirtd.service - Virtualization daemon
     Loaded: loaded (/lib/systemd/system/libvirtd.service; enabled)
     Active: active (running) since ...
```

✅ **Status `active (running)`? Lanjut!**

---

### LANGKAH 4: Install Cockpit

Install Cockpit beserta modul `cockpit-machines` untuk manajemen VM melalui antarmuka web.

```bash
sudo apt install -y cockpit cockpit-machines
```

**Penjelasan paket:**

| Paket | Fungsi |
|---|---|
| `cockpit` | Dashboard manajemen server berbasis web |
| `cockpit-machines` | Modul tambahan untuk manajemen VM/KVM di dalam Cockpit |

Aktifkan dan jalankan service Cockpit:

```bash
sudo systemctl enable --now cockpit.socket
```

**Penjelasan:**
- `enable` → Cockpit otomatis aktif setiap kali server reboot
- `--now` → Langsung jalankan sekarang tanpa perlu reboot

#### Verifikasi: Cek Status Cockpit

```bash
sudo systemctl status cockpit.socket
```

**Output yang diharapkan:**
```
● cockpit.socket - Cockpit Web Service Socket
     Loaded: loaded (/lib/systemd/system/cockpit.socket; enabled)
     Active: active (listening) since ...
```

✅ **Status `active (listening)`? Lanjut!**

---

### LANGKAH 5: Konfigurasi Pengguna

Tambahkan user Anda ke grup `libvirt` dan `kvm` agar bisa mengelola VM tanpa harus selalu pakai `sudo`.

```bash
sudo usermod -aG libvirt $USER
sudo usermod -aG kvm $USER
```

**Penjelasan:**
- `usermod -aG` → Tambah user ke grup tanpa menghapus grup lain yang sudah ada
- `$USER` → Otomatis mengambil nama user yang sedang login

> ⚠️ **PENTING:** Setelah menjalankan perintah ini, **logout lalu login kembali** agar perubahan grup aktif di sesi baru. Tanpa ini, perintah `virsh` bisa muncul permission error.

---

### LANGKAH 6: Akses Dashboard Cockpit

Buka browser dan akses Cockpit melalui:

```
https://<IP-SERVER>:9090
```

Gunakan **username dan password Linux** yang sudah ditambahkan ke grup `libvirt` tadi.

> **Catatan:** Cockpit menggunakan HTTPS dengan self-signed certificate secara default. Jika muncul peringatan keamanan di browser, klik **Advanced → Proceed** (atau "Lanjutkan") untuk tetap mengakses.

✅ **Dashboard Cockpit muncul? Lanjut ke konfigurasi jaringan!**

---

### LANGKAH 7: Konfigurasi Jaringan Virtual

libvirt menyediakan jaringan virtual bernama `default` yang menggunakan mode NAT. Jaringan ini digunakan oleh VM agar bisa akses internet melalui host.

#### Langkah 7.1: Aktifkan Jaringan Default

```bash
sudo virsh net-start default
```

**Output:**
```
Network default started
```

#### Langkah 7.2: Set Autostart saat Boot

```bash
sudo virsh net-autostart default
```

**Output:**
```
Network default marked as autostarted
```

#### Langkah 7.3: Verifikasi Status Jaringan

```bash
sudo virsh net-list --all
```

**Output yang diharapkan:**
```
 Name      State    Autostart   Persistent
--------------------------------------------
 default   active   yes         yes
```

**Penjelasan kolom:**
- **State: active** → Jaringan sedang berjalan
- **Autostart: yes** → Otomatis aktif saat server reboot
- **Persistent: yes** → Konfigurasi tersimpan permanen

✅ **Jaringan default sudah aktif dan autostart! Instalasi selesai!** 🎉

---

### LANGKAH 8: Konfigurasi Port Alternatif (Opsional)

Jika port `9090` tidak dapat diakses — misalnya terblokir firewall, digunakan aplikasi lain, atau kebijakan jaringan — Cockpit bisa dipindahkan ke port lain, contohnya `29090`.

#### Langkah 8.1: Buat Direktori Override

```bash
sudo mkdir -p /etc/systemd/system/cockpit.socket.d/
```

#### Langkah 8.2: Buat File Konfigurasi Override

```bash
sudo bash -c 'cat <<EOF > /etc/systemd/system/cockpit.socket.d/override.conf
[Socket]
ListenStream=
ListenStream=29090
EOF'
```

> ⚠️ **Catatan:** Baris `ListenStream=` yang **kosong** wajib disertakan. Fungsinya untuk menghapus konfigurasi port default (`9090`) sebelum menetapkan port baru. Tanpa baris ini, kedua port akan aktif bersamaan.

#### Langkah 8.3: Reload dan Restart Service

```bash
sudo systemctl daemon-reload
sudo systemctl restart cockpit.socket
```

#### Langkah 8.4: Verifikasi Konfigurasi

```bash
cat /etc/systemd/system/cockpit.socket.d/override.conf
```

**Output yang diharapkan:**
```ini
[Socket]
ListenStream=
ListenStream=29090
```

#### Langkah 8.5: Akses Cockpit di Port Baru

```
https://<IP-SERVER>:29090
```

✅ **Cockpit berhasil diakses di port baru!**

## Cara Membuat Virtual Machine Pertama

Setelah semua komponen terinstall, berikut cara membuat VM pertama via Cockpit dengan benar — termasuk konfigurasi CPU sebelum VM dijalankan.

> ⚠️ **PENTING:** Gunakan **"Create and edit"**, bukan "Create and run". Opsi "Create and edit" membuka halaman konfigurasi lanjutan sebelum VM dinyalakan — di sinilah kita bisa mengatur jumlah vCPU yang diizinkan digunakan oleh VM. Jika langsung "Create and run", pengaturan CPU default akan dipakai dan tidak bisa diubah saat VM sedang berjalan.

---

### Langkah A: Siapkan File ISO

Siapkan file ISO OS yang ingin diinstall (misal: Debian, Ubuntu Server, Kali Linux, dll.).

Jika ISO ada di komputer lokal, upload ke direktori images di server:

```bash
scp debian-12.iso username@192.168.x.x:/var/lib/libvirt/images/
```

---

### Langkah B: Buat VM di Cockpit

**1.** Buka Cockpit di browser, masuk ke menu **"Virtual Machines"** di sidebar kiri.

**2.** Klik tombol **"Create VM"**.

**3.** Isi form pembuatan VM:

| Field | Keterangan |
|---|---|
| **Name** | Nama VM, misal: `debian-server-01` |
| **Installation type** | Pilih `Local install media (ISO image)` |
| **Installation source** | Browse ke file ISO yang sudah diupload |
| **Storage** | Tentukan ukuran disk VM (misal: 20 GB) |
| **Memory** | Tentukan RAM VM (misal: 2048 MB) |

**4.** Klik **"Create and edit"** — jangan klik "Create and run"!

Cockpit akan membuat VM dan langsung membuka halaman **detail konfigurasi VM**.

---

### Langkah C: Edit Jumlah vCPU (PENTING!)

Setelah klik "Create and edit", Anda akan masuk ke halaman detail VM. Di sinilah konfigurasi CPU diatur sebelum VM dinyalakan.

**1.** Scroll ke bagian **"Overview"** atau **"CPU"** pada halaman detail VM.

**2.** Cari field **"vCPU count"** (jumlah virtual CPU yang dialokasikan ke VM).

**3.** Klik tombol **edit** (ikon pensil) di sebelah nilai vCPU.

**4.** Atur nilai sesuai kebutuhan:

| Field | Penjelasan |
|---|---|
| **vCPU count** | Total jumlah vCPU yang terlihat oleh OS di dalam VM |
| **vCPU maximum** | Batas maksimum vCPU yang bisa di-hotplug ke VM |
| **Sockets** | Jumlah soket CPU virtual (biasanya biarkan `1`) |
| **Cores per socket** | Jumlah core per soket — ini yang paling sering diubah |
| **Threads per core** | Jumlah thread per core (isi `2` jika CPU host support hyperthreading) |

> **Contoh:** Jika ingin VM punya 4 vCPU → set **Sockets: 1**, **Cores per socket: 4**, **Threads per core: 1**

**5.** Klik **"Apply"** untuk menyimpan perubahan.

> **Catatan:** Jumlah vCPU yang dialokasikan ke VM **tidak boleh melebihi jumlah core fisik** yang dimiliki host. Cek jumlah core host dengan perintah:
> ```bash
> nproc
> ```

---

### Langkah D: Jalankan VM

Setelah konfigurasi CPU selesai:

**1.** Klik tombol **"Run"** atau **Install** di bagian atas halaman detail VM, persis di samping nama VM yang telah dibuat.

**2.** Klik **"Console"** untuk membuka tampilan layar VM langsung di browser.

**3.** Ikuti proses instalasi OS seperti biasa di dalam console tersebut.

✅ **VM berhasil dibuat dengan konfigurasi CPU yang tepat!** 🎉

## Troubleshooting — Kalau Ada Masalah

### Masalah 1: Hasil `egrep -c '(vmx|svm)'` adalah `0`

**Gejala:** Output perintah cek CPU mengembalikan angka `0`

**Penyebab:** Fitur virtualisasi hardware belum diaktifkan di BIOS/UEFI, atau CPU memang tidak mendukung.

**Solusi:**

#### Step 1: Masuk ke BIOS/UEFI

Restart server dan tekan tombol BIOS saat booting (biasanya `Del`, `F2`, atau `F10`).

#### Step 2: Aktifkan Virtualisasi

Cari dan aktifkan opsi:
- Intel: **"Intel Virtualization Technology"** atau **"Intel VT-x"**
- AMD: **"AMD-V"** atau **"SVM Mode"**

Ubah ke **Enabled**, lalu **Save dan reboot**.

#### Step 3: Cek Ulang

```bash
egrep -c '(vmx|svm)' /proc/cpuinfo
```

> Jika CPU memang tidak punya fitur virtualisasi hardware (umumnya CPU lama atau low-end), KVM tidak bisa digunakan. Pertimbangkan VirtualBox sebagai alternatif.

---

### Masalah 2: `libvirtd` Tidak Berjalan

**Gejala:** `sudo systemctl status libvirtd` menampilkan `inactive` atau `failed`

**Penyebab:** Instalasi tidak lengkap atau ada konflik paket.

**Solusi:**

#### Step 1: Cek Log Error

```bash
sudo journalctl -u libvirtd -n 50
```

#### Step 2: Coba Start Manual

```bash
sudo systemctl start libvirtd
```

#### Step 3: Install Ulang jika Perlu

```bash
sudo apt remove --purge qemu-kvm libvirt-daemon-system
sudo apt install -y qemu-kvm libvirt-daemon-system libvirt-clients bridge-utils virtinst
```

---

### Masalah 3: Tidak Bisa Akses Cockpit di Port 9090

**Gejala:** Browser menampilkan "This site can't be reached" atau connection timeout

**Penyebab:** Port terblokir firewall, atau service Cockpit tidak berjalan.

**Solusi:**

#### Step 1: Cek Status Service

```bash
sudo systemctl status cockpit.socket
```

#### Step 2: Cek dan Buka Firewall

```bash
sudo ufw status
```

Jika UFW aktif, izinkan port Cockpit:

```bash
sudo ufw allow 9090/tcp
sudo ufw reload
```

#### Step 3: Cek Port yang Didengarkan

```bash
sudo ss -tlnp | grep cockpit
```

#### Step 4: Restart Service

```bash
sudo systemctl restart cockpit.socket
```

---

### Masalah 4: Permission Denied Saat Jalankan `virsh`

**Gejala:** Muncul error `authentication unavailable` atau `permission denied`

**Penyebab:** User belum masuk ke grup `libvirt`, atau perubahan grup belum aktif di sesi ini.

**Solusi:**

#### Step 1: Cek Grup User

```bash
groups $USER
```

Harus ada `libvirt` dan `kvm` di output.

#### Step 2: Tambahkan Ulang jika Belum Ada

```bash
sudo usermod -aG libvirt $USER
sudo usermod -aG kvm $USER
```

#### Step 3: Logout dan Login Kembali

Setelah login ulang, coba lagi:

```bash
virsh list --all
```

---

### Masalah 5: Jaringan `default` Gagal di-start

**Gejala:** `sudo virsh net-start default` muncul error

**Penyebab:** Jaringan default belum terdefinisi, atau ada konflik konfigurasi jaringan.

**Solusi:**

#### Step 1: Cek Daftar Jaringan

```bash
sudo virsh net-list --all
```

#### Step 2: Buat Ulang dari Template Bawaan (jika `default` tidak ada)

```bash
sudo virsh net-define /usr/share/libvirt/networks/default.xml
sudo virsh net-start default
sudo virsh net-autostart default
```

#### Step 3: Cek Log Error

```bash
sudo journalctl -u libvirtd -n 30
```

---

### Masalah 6: Cockpit Tidak Menampilkan Menu "Virtual Machines"

**Gejala:** Dashboard Cockpit terbuka tapi tidak ada menu Virtual Machines di sidebar

**Penyebab:** Paket `cockpit-machines` belum terinstall atau belum terbaca.

**Solusi:**

#### Step 1: Install Ulang Modul

```bash
sudo apt install --reinstall cockpit-machines
```

#### Step 2: Restart Cockpit

```bash
sudo systemctl restart cockpit.socket
```

#### Step 3: Hard Refresh Browser

Tekan `Ctrl + Shift + R` di browser, lalu login ulang ke Cockpit.

---

### Masalah 7: Port Override Tidak Berfungsi

**Gejala:** Setelah konfigurasi port alternatif, Cockpit masih di port lama atau tidak bisa diakses

**Penyebab:** File override tidak terbaca atau format konfigurasi salah.

**Solusi:**

#### Step 1: Cek Isi File Override

```bash
cat /etc/systemd/system/cockpit.socket.d/override.conf
```

Pastikan ada **2 baris** `ListenStream` — satu kosong, satu berisi port baru.

#### Step 2: Cek Apakah systemd Sudah Membaca Konfigurasi

```bash
sudo systemctl show cockpit.socket | grep Listen
```

#### Step 3: Ulangi Reload dan Restart

```bash
sudo systemctl daemon-reload
sudo systemctl restart cockpit.socket
```

#### Step 4: Izinkan Port Baru di Firewall

```bash
sudo ufw allow 29090/tcp
sudo ufw reload
```

## Perintah Penting untuk Dicatat

```bash
# Cek dukungan virtualisasi CPU
egrep -c '(vmx|svm)' /proc/cpuinfo

# Cek status libvirt
sudo systemctl status libvirtd

# Cek status Cockpit
sudo systemctl status cockpit.socket

# Daftar semua VM
sudo virsh list --all

# Daftar jaringan virtual
sudo virsh net-list --all

# Start / stop jaringan default
sudo virsh net-start default
sudo virsh net-destroy default

# Start / stop VM tertentu

# Restart Cockpit
sudo systemctl restart cockpit.socket

# Restart libvirt
sudo systemctl restart libvirtd

# Cek log libvirt
sudo journalctl -u libvirtd -n 50

# Cek log Cockpit
sudo journalctl -u cockpit -n 50
```

## Konsep Penting yang Perlu Dipahami

### 1. Tipe Hypervisor

**Type-1 (Bare-metal) — KVM:**
- Langsung berjalan di atas hardware
- Tidak butuh Host OS terpisah
- Performa lebih tinggi, latensi lebih rendah
- Contoh: KVM, VMware ESXi, Hyper-V

**Type-2 (Hosted):**
- Berjalan di atas Host OS yang sudah ada
- Lebih mudah diinstall, cocok untuk desktop
- Performa sedikit lebih rendah karena ada lapisan OS tambahan
- Contoh: VirtualBox, VMware Workstation

### 2. Cara Kerja KVM + QEMU + libvirt

```
[ Cockpit / virsh (User Interface) ]
              ↓
        [ libvirt API ]
              ↓
    [ QEMU (Hardware Emulation) ]
              ↓
      [ KVM (Kernel Module) ]
              ↓
   [ Hardware Fisik (CPU/RAM/Disk) ]
```

Setiap lapisan punya peran masing-masing — user tidak perlu berinteraksi langsung dengan lapisan bawah.

### 3. Tipe Jaringan VM di libvirt

**NAT (Default):**
- VM bisa akses internet melalui IP host
- Host bisa akses VM, tapi device lain di jaringan tidak bisa langsung akses VM
- Cocok untuk development dan testing

**Bridge:**
- VM mendapat IP langsung dari router/DHCP jaringan
- VM terlihat seperti device fisik biasa di jaringan
- Cocok untuk server production yang perlu diakses dari luar

**Isolated:**
- VM hanya bisa komunikasi sesama VM dalam jaringan yang sama
- Tidak ada akses keluar sama sekali
- Cocok untuk lab environment yang terisolasi
